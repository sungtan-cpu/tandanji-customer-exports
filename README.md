# 먼딜 · 3팩 40% 고객 파일 업무

다른 Windows PC에서 이어서 실행하기 위한 업무 지시서와 실행 도구입니다. 기존 명칭인 **반값**은 현재 **3팩 40% 첫구매 고객** 업무를 뜻합니다. 업로드 파일명은 호환을 위해 `반값구매고객_시작일_종료일`을 유지합니다.

## 시작 순서

1. [업무지시서.md](업무지시서.md): 조회·가공·보고 규칙.
2. [다른PC설치.md](다른PC설치.md): 설치, 로그인, Google Chat 연결, 실제 테스트.
3. [브라우저준비.md](브라우저준비.md): 내장 브라우저를 쓸 때 원본과 검색 증빙 준비.
4. [AGENTS.md](AGENTS.md): 이 폴더를 연 에이전트가 따라야 할 실행 지침.
5. [정기작업프롬프트.md](정기작업프롬프트.md): 새 PC에서 정기 작업을 등록할 때 사용할 문구.

| 업무 | 한국 시간 실행 | 주문일 범위 | 상품명 | 첫주문 | 탈퇴회원 |
|---|---|---|---|---|---|
| 먼딜 | 매월 2일 09:30 | 전월 20일~말일 | 먼딜 | 해제 | 포함 |
| 3팩 40% / 기존 반값 | 매월 20일 09:30 | 전월 20일~당월 19일 | rules.json의 해당 기간 상품명 모두 | 체크 | 제외 |

매월 두 업무 모두 **원래 업무 예정 월의 다음 달** 폴더에 보관합니다. 예: 2026년 11월 업무 → `바탕화면/먼딜/12월 먼딜준비`. 재실행 날짜 때문에 폴더가 바뀌지 않습니다.

## 빠른 실행

공개 주소: https://github.com/sungtan-cpu/tandanji-customer-exports

이 폴더에서 Python 3.11 이상, Node.js 20 이상을 사용합니다.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
npm install
Copy-Item config.example.json config.local.json
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

브라우저 로그인과 Chat 설정 후 **새 PC별로 먼저 `--test`**로 실제 다운로드·검증·저장·알림을 끝내야 정상 실행이 열립니다. 테스트 파일명에는 `_테스트`가 붙습니다.

```powershell
# 원래 업무 예정일을 지정한다. 아래는 날짜 예시다.
.\.venv\Scripts\python.exe run.py --job mundil --scheduled-date 2026-11-02 --test
.\.venv\Scripts\python.exe run.py --job half --scheduled-date 2026-11-20 --test
# 테스트 성공 후 정상 실행
.\.venv\Scripts\python.exe run.py --job mundil --scheduled-date 2026-11-02
.\.venv\Scripts\python.exe run.py --job half --scheduled-date 2026-11-20
```

`--no-notify`는 파일만 검증하며 전체 완료·운영 전환 성공으로 기록하지 않습니다. `--start/--end`는 사용자가 요청한 별도 기간에만 사용합니다. 종료일이 끝나지 않은 현재 진행본은 이 이전용 도구에서 거부합니다.

## 이관 내용과 검증 범위

- 기존 고도몰 HTML/XLSX/암호 ZIP 파서, 주문번호 중복·0원 제외, 상품별 적용 시각 처리를 재사용했습니다.
- 기존 PC의 절대경로, 전용 Codex 런타임, 예전 채팅 기록에서 웹훅을 찾던 의존성을 없앴습니다.
- 이전용 도구는 공개 Python 라이브러리 `openpyxl`로 XLSX 생성·재검증 후 CSV를 씁니다. 기존 PC에서 운영 중인 프로그램은 수정하지 않았습니다.
- 개인정보 없는 자동 테스트로 날짜·윤년·연도 경계, 원본 파싱, 검색 증빙, 상품 적용 시각, 중복·0원 제외, 누락 이메일, 전화번호 문자열, 파일 값 일치·해시·덮어쓰기 방지 등을 검사합니다.
- 새 PC의 고도몰 화면·로그인·실제 다운로드·Chat 전송은 **그 PC에서 실제 테스트해야 합니다**. 이 저장소를 올렸다는 사실만으로 원격 PC 실운영까지 확인된 것은 아닙니다.
- Chrome 자동 다운로드는 상품별 500건 미만일 때 동작합니다. 500건 이상이면 부분 결과를 완료하지 않고 중단합니다. [브라우저준비.md](브라우저준비.md)에 따라 모든 페이지를 수집한 준비 원본으로 처리하세요.

## 보관 경계

GitHub에는 코드·설정 예시·업무 문서·가상 테스트만 보관합니다. 고객 원본, 최종 파일, 고객 이름/전화/이메일/주문번호, 실제 처리 보고서, 브라우저 프로필, 다운로드 암호, 웹훅 주소는 포함하지 않습니다. `work/`, `results/`, `config.local.json`, `.env`, 각종 고객 파일 확장자는 `.gitignore`에 제외했습니다.

공개본에는 실제 관리자 도메인과 Chat 방 식별자도 넣지 않았습니다. `YOUR_GODOMALL_ADMIN_HOST`, `YOUR_CHAT_SPACE_ID`를 새 PC 로컬 설정에서 바꿉니다. 실제 로그인 아이디·비밀번호·인증 토큰은 저장소에 보관하지 않습니다. 이 공개 저장소는 누구나 볼 수 있으므로 실제 설정/고객 파일을 나중에 추가하지 마세요. `.gitignore`는 실수 방지 장치이며 이미 추적된 파일이나 강제 추가 파일까지 보호하는 보안 저장소가 아닙니다.

실제 결과를 다른 PC로 옮길 때는 Git 밖에서 승인된 안전한 방법으로 해당 `results/<작업키>` 전체를 옮겨야 중복 생성·전송 기록을 이어받을 수 있습니다. 폴더를 복사한 뒤 결과 JSON의 이전 PC 경로를 새 PC 경로로 맞추고 해시를 재검증합니다. 고객 파일을 Git에 추가하지 마세요.

GitHub Actions에서 고객 추출을 실행하지 않습니다. 로그인된 로컬 PC 또는 에이전트 브라우저가 필요합니다. 새 PC 정기 실행은 실제 테스트 후 별도로 등록하며 기존 PC와 동시에 같은 월을 실행하지 않습니다.
